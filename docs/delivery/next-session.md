# Продолжение работы

## Точка остановки
Пользователь попросил сохранить все ответы интервью и текущее состояние,
закоммитить и отправить в remote, а проектирование продолжить в следующую сессию.
Реализацию приложений не начинать автоматически из этого документа.

Подготовлены:
- WIP-структура `apps/`, `infra/`, проектные инструкции и реестр исходных требований.
- OpenSpec `spec-driven`, адаптеры OpenCode, Claude Code и Codex.
- [Все ответы INT-001–INT-096](../product/planning-interview.md), включая пересмотр мобильной авторизации и Unleash.
- [Механизм согласования](../product/approval-workflow.md), [краткий журнал](../product/approval-packages.md).
- [Превентивные меры нагрузки](../architecture/load-planning.md).

## Статус OpenSpec
Change: `bootstrap-local-environment`, каталог `openspec/changes/bootstrap-local-environment/`.
Первый локальный сценарий реализован и проверен с временным источником.
Команды и границы проверки: [локальный запуск](../../README.md).
Основные `openspec/specs/` пока пусты.

## Следующий порядок работы
1. Прочитать `AGENTS.md`, интервью, реестр вопросов и [журнал согласования](../product/approval-packages.md).
2. Ответ о записи коллег зафиксирован в журнале. Текст ответа на первое письмо
   об отмене получить из переписки Кирилла. Следующие два письма подготовлены,
   но не отправлены. После отправки отметить факт, после ответа — точные решения.
3. Параллельно разобраться, как автоматически поднять настоящий Битрикс
   на чистой машине. Пробная версия доступна; условия её использования и способ
   установки — внутренняя техническая задача. Так же проверить доставку двойников:
   локальный product-test — отдельный репозиторий, исключённый из корневого Git.
   Эти вопросы не адресовать клиенту как продуктовые решения.
4. Разобрать оставшиеся открытые вопросы по статусам реестра; Q-015 закрыт.
5. Составить первоначальную оценку при 30 часах в неделю с резервом на приёмку;
   отделить обязательное ТЗ от расширений интервью. Даты и оборудование пока не подтверждены.
6. После принятия результата архивировать change. Подключение настоящего
   Битрикса проектировать отдельным изменением; участие и оплата в него не входят.

## Не забыть при оценке
Предложения сверх явно расписанного в ТЗ: мобильная авторизация уже сейчас,
автосинхронизация прав Битрикса, Unleash, фоновые экспорты с защищённым скачиванием,
административный повтор задач, копии/проверка восстановления и уведомления сопровождению.
Всё это подтверждено для планирования, но не согласовано заказчиком и не оценено.
Партнёрские воркшопы — только дополнительное задание, подробно ещё не проектировались.

## Проверки и ограничения на момент подготовки
- Symfony, Next.js и PostgreSQL запущены с локальным источником; двойники не запускались.
- Готовность полного проекта, CI и промышленной эксплуатации не проверялась.
- Проверки документов и Git выполняются перед фиксацией; результат коммита/push
  сообщается в итоговом ответе, а не предсказывается этим файлом.
- Не считать отсутствие ошибок Markdown или готовность proposal доказательством готовности продукта.

## Быстрый вход
```sh
git status --short
openspec list
openspec status --change bootstrap-local-environment
```
В OpenCode: `/opsx-update bootstrap-local-environment` для актуализации плановых
артефактов; прежде получить актуальный контекст и разрешить материальные неоднозначности.
