# local-environment Specification

## Purpose

Воспроизводимый локальный запуск позволяет проверить первый публичный путь данных через API и сайт без ручной установки приложений; его готовность отличается от готовности продукта к итоговой приёмке.

## Requirements

### Requirement: Локальный запуск первого сценария
Система SHALL предоставлять документированную команду, которая на чистой Linux-машине с Git, Docker Engine, Compose v2 и доступом к необходимым образам и пакетам подготавливает и запускает локально PostgreSQL, Symfony API, Next.js и временный источник контента без ручной установки приложений. Связь: OPS-005, TECH-001; промежуточный сценарий, не полное выполнение OPS-005.

#### Scenario: Первый запуск
- **WHEN** разработчик получает репозиторий на указанной машине и выполняет команду запуска
- **THEN** сервисы запускаются с подготовленной конфигурацией и схемой данных, а публичные страницы доступны по документированным адресам

#### Scenario: Сбой подготовки
- **WHEN** обязательная зависимость не готова или подготовка завершается ошибкой
- **THEN** команда возвращает ошибку с указанием неготового шага, а система не сообщает об успешной готовности

### Requirement: Временный источник только для локальной разработки
Система SHALL получать демонстрационный контент через отдельную границу импорта из явно выбранного временного источника, доступного только в локальном режиме; обычный режим продукта SHALL не запускаться с этим источником. Связь: CMS-004, CMS-001; временная проверка пути данных, не подтверждение происхождения контента из Битрикса.

#### Scenario: Локальное получение контента
- **WHEN** локальное окружение запускается с временным источником
- **THEN** контент попадает в API через путь получения контента, а не через ручную запись непосредственно в базу Symfony

#### Scenario: Временный источник вне локального режима
- **WHEN** конфигурация обычного режима указывает на временный источник
- **THEN** запуск отказывается считать такую конфигурацию рабочей

### Requirement: Проверка готовности и повторный запуск
Система SHALL предоставлять локальную проверку готовности API, сайта и доступности демонстрационного контента и SHALL сохранять данные при повторном запуске без явной команды удаления. Связь: OPS-005, OPS-004.

#### Scenario: Проверка работающего сценария
- **WHEN** все сервисы готовы и контент получен
- **THEN** проверка подтверждает доступность API и страниц списка и отдельного мероприятия

#### Scenario: Повтор после остановки
- **WHEN** разработчик останавливает и повторно запускает окружение без команды очистки
- **THEN** ранее сохранённые данные остаются, а демонстрационное мероприятие не дублируется
