# Spec Delta

## Purpose

Публичный просмотр мероприятий через единый API даёт проверяемую первую вертикаль от источника контента до каталога и страницы, не обещая ещё регистрацию и полный функционал каталога.

## ADDED Requirements

### Requirement: Публичный список мероприятий
Система SHALL предоставлять гостю базовый список опубликованных демонстрационных мероприятий через Symfony API и страницу каталога, читающую этот API. Связь: CAT-001, API-001; поиск, фильтры и полный каталог остаются за рамками первого сценария.

#### Scenario: Список доступен
- **WHEN** источник передал опубликованное мероприятие и гость открывает каталог
- **THEN** он видит мероприятие с названием, городом и временем начала, полученными из Symfony API

#### Scenario: Нет опубликованных мероприятий
- **WHEN** у API нет опубликованных мероприятий
- **THEN** каталог показывает пустое состояние, а не ошибку или фиктивные записи

### Requirement: Публичная страница мероприятия
Система SHALL предоставлять отдельную страницу опубликованного мероприятия по устойчивому идентификатору через Symfony API с описанием, программой, спикерами, площадкой, датой, временем и часовым поясом. Связь: EVT-001, API-001; это первая часть полного требования к странице.

#### Scenario: Открытие страницы
- **WHEN** гость переходит из каталога по ссылке мероприятия
- **THEN** страница показывает перечисленные поля из ответа API, включая явно указанный часовой пояс начала

#### Scenario: Неизвестное или неопубликованное мероприятие
- **WHEN** гость открывает ссылку с неизвестным идентификатором либо на неопубликованное мероприятие
- **THEN** API не раскрывает его публичный контент, а страница показывает состояние «не найдено»

### Requirement: Без ложного остатка мест
Система SHALL не представлять демонстрационную вместимость или данные контента как подтверждённое количество свободных мест до появления авторитетного учёта записей. Связь: EVT-002; честный остаток ещё не реализован.

#### Scenario: Просмотр до появления записи
- **WHEN** гость открывает каталог или страницу мероприятия в первом сценарии
- **THEN** интерфейс не показывает число свободных мест и не предлагает действие записи

### Requirement: Состояние недоступного API
Система SHALL показывать понятное состояние ошибки, если контент нельзя получить из Symfony API, не выдавая ошибку за пустой каталог или отсутствие мероприятия. Связь: CAT-001, EVT-001, OPS-004.

#### Scenario: Ошибка получения каталога
- **WHEN** запрос каталога к Symfony API завершается ошибкой
- **THEN** страница показывает состояние ошибки отдельно от пустого списка
